## 1. 架构目标与原则

**目标**：自托管、低运维成本、隐私优先、跨端体验一致。

**设计原则**

| 编号 | 原则 | 含义 |
|---|---|---|
| P1 | 组件极简 | 能少一个组件就少一个：不引入 Redis / 独立消息队列，用 PostgreSQL 任务表实现异步流水线 |
| P2 | 数据自持 | 一切数据可备份为文件（pg_dump + 快照目录），可随时迁移重建 |
| P3 | 厂商无锁定 | LLM 走 OpenAI 兼容协议，换厂商只改环境变量；embedding 模型可替换（重嵌入路径明确） |
| P4 | 前后端分离 | 客户端只依赖 REST API；API 可被未来的浏览器插件、脚本等第三方复用 |
| P5 | 一切耗时操作异步化 | 抓取、LLM 分析、向量化全部进任务表，API 只做受理与查询 |

## 2. 总体架构

### 2.1 系统上下文

```
 用户 ──► Flutter 客户端（Android / Windows / macOS / Linux）
                    │ HTTPS (REST + JWT, SSE)
                    ▼
          知识匣服务端（自托管 Docker）
                    │
                    ├──► OpenAI 兼容 LLM API（云端 DeepSeek/Qwen/GLM/OpenAI 或本地推理）
                    ├──► 本地 embedding 模型 bge-small-zh-v1.5（进程内推理，不出网）
                    └──► 目标网页（HTTP 抓取，可选无头浏览器兜底）
```

### 2.2 容器图

```
┌───────────────────────── docker compose ─────────────────────────┐
│                                                                  │
│  [proxy · 可选]  Caddy / Nginx  :443 TLS ──► api:8000             │
│                                                                  │
│  [api]   FastAPI + uvicorn                                       │
│          · REST /api/v1（auth / articles / search / tags /       │
│            annotations / admin）                                 │
│          · JWT 鉴权、参数校验、user_id 隔离                        │
│          · 受理任务：写 articles + jobs                           │
│                                                                  │
│  [worker] 同一镜像、不同启动命令                                   │
│          · 任务循环：FOR UPDATE SKIP LOCKED 领取 jobs             │
│          · extract : httpx + trafilatura（可选 Playwright 兜底）   │
│          · analyze : OpenAI 兼容客户端 → 摘要 + tags               │
│          · embed   : sentence-transformers（bge-small-zh 进程内）  │
│                                                                  │
│  [db]    postgres:16 + pgvector + pg_trgm                        │
│          元数据 / 正文 / tsvector 全文索引 / 向量 / jobs 队列       │
│                                                                  │
│  volumes:  pg_data（数据库）  app_data（HTML 快照）  hf_cache（模型）│
└──────────────────────────────────────────────────────────────────┘
  可选 profile [render]:  browserless/chrome（JS 渲染兜底，worker 经 CDP 连接）
```

**要点**

- `api` 与 `worker` 使用**同一镜像、不同入口命令**（`uvicorn` vs `python -m app.workers.runner`），构建一次、部署两份，保证逻辑同步。
- api 启动时自动执行 `alembic upgrade head`，迁移失败拒绝启动（单实例部署下安全）。
- 常驻容器仅 3 个：`db` / `api` / `worker`；`render`（无头浏览器）与 `proxy` 为可选 profile，按需启用。
- 请求处理总览：
  - **写路径**：客户端 → api（鉴权 / 校验 / 落库）→ jobs 表 → worker 异步执行 → 状态回写 → 客户端轮询；
  - **读路径**：客户端 → api → PostgreSQL（FTS / 向量）→ 融合排序 → 返回。

## 3. 技术选型

### 3.1 选型总表

| 层 | 选型 | 版本基线 | 理由 | 否决的备选 |
|---|---|---|---|---|
| API 框架 | Python + FastAPI | Python 3.12 | 异步友好、Pydantic 校验、LLM / 抽取生态最全 | Go（抽取与 LLM 工具链弱）、Node.js（次优） |
| ORM / 迁移 | SQLAlchemy 2 + Alembic | 2.0 | 成熟、类型友好、迁移可控 | — |
| 数据库 | PostgreSQL 16 + pgvector + pg_trgm | pgvector ≥ 0.7 | 一库承担关系数据 / 全文索引 / 向量，备份恢复统一 | 独立向量库（Qdrant / Milvus）与当前规模不匹配，多一个组件 |
| 正文抽取 | trafilatura | 最新稳定 | 中文页面抽取质量与速度最优，纯 Python | readability-lxml（质量略逊，作兜底） |
| JS 渲染兜底 | Playwright + browserless/chrome | 可选 profile | 仅对疑似 JS 渲染失败页面启用 | 常驻多占 ~1GB 内存，故默认不启 |
| LLM 接入 | openai SDK（OpenAI 兼容协议） | — | 一套代码接入所有兼容厂商与本地推理 | 各厂商私有 SDK（锁定风险） |
| Embedding | sentence-transformers + BAAI/bge-small-zh-v1.5 | 512 维 | 中文效果好、常驻内存 ~150MB 满足 2GB 总预算、离线免费（bge-m3 为内存充裕时的质量升级项） | 云 embedding API（出网 + 按量计费）；Ollama（多占一个容器，列为演进项） |
| 中文分词 | jieba（应用层，`cut_for_search`） | — | 免去自编译 zhparser 镜像，官方 PG 镜像即可 | zhparser（质量更好但需自定义镜像，列为演进项） |
| 客户端 | Flutter + Riverpod + go_router + dio | Flutter 3.24+ | 一套代码五端、原生系统分享入口、渲染性能好 | React Native（桌面端弱）；PWA（无原生分享入口） |
| 认证 | JWT(HS256) + bcrypt + 可吊销 refresh | bcrypt 官方库（passlib 已停更，直接使用 bcrypt） | access 无状态高性能，refresh 落库可吊销 | session（需黏性）、纯无状态长期 token（不可吊销） |
| 工程工具链 | uv + ruff + mypy | Python 3.12 | 快速安装、原生 lockfile、统一 lint 与类型检查 | poetry / pip-tools |

### 3.2 关键决策记录（ADR 摘要）

- **ADR-1 用 PG 任务表做队列，而非 Redis / Celery**：本系统任务量低频（每张卡 3 个任务），`SELECT … FOR UPDATE SKIP LOCKED` 完全够用；少一个组件即少一分运维成本；任务天然持久化，重启不丢。若未来吞吐不足，可平滑替换为 arq（接口层不变）。
- **ADR-2 中文全文检索用应用层 jieba 分词写入 tsvector**（`to_tsvector('simple', 空格连接的分词结果)`），而非 zhparser 扩展：避免自定义 PG 镜像，分词质量在应用侧可控、可升级。代价：正文变更时需在任务中重算该列（流水线已覆盖）。
- **ADR-3 每卡单向量，而非分块多向量**：本系统的检索主体是「找回那张卡」，而非「定位文中片段」；用「标题 + 摘要 + 各级小节标题 + 正文前段」拼接成单向量已能保证召回。分块多向量 + 片段级高亮列为演进项。
- **ADR-4 批注锚定用「quote + 前后文 + 出现序号」文本锚，而非 DOM / CSS 路径**：阅读视图是 Markdown 重排渲染，DOM 结构在客户端渲染器内部，跨端不可移植；文本锚在重排后仍可定位，且服务端存储与渲染器解耦。源串偏移与渲染 span 的映射存在实现复杂度，M3 开工前先做 spike 验证（见 6.3）。
- **ADR-5 refresh token 落库（哈希存储）并轮换**：支持吊销（改密码 / 登出 / 管理员封禁）与被盗检测（旧 token 复用即触发吊销链）。
- **ADR-6 embedding 维度固定为列类型**（`vector(512)`）：pgvector 列维度不可变更，换模型 = `ALTER TYPE` + 全量重嵌入，由管理命令一次性完成，避免维度漂移导致的静默检索劣化。

### 4.2 数据库设计

DDL（要点版，最终以 Alembic 迁移为准）：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  username      VARCHAR(32)  NOT NULL UNIQUE,          -- [A-Za-z0-9_-]，1-32位，区分大小写
  password_hash VARCHAR(128) NOT NULL,          -- bcrypt
  is_admin      BOOLEAN      NOT NULL DEFAULT FALSE,
  is_active     BOOLEAN      NOT NULL DEFAULT TRUE,
  settings      JSONB        NOT NULL DEFAULT '{}',   -- 预留：个性化配置
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE refresh_tokens (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash VARCHAR(64) NOT NULL,                 -- sha256(随机token)
  expires_at TIMESTAMPTZ NOT NULL,
  revoked    BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_refresh_user ON refresh_tokens (user_id);

CREATE TABLE articles (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  url           TEXT        NOT NULL,
  url_hash      VARCHAR(64) NOT NULL,            -- 规范化URL的sha256（用户内去重）
  domain        VARCHAR(255),
  title         TEXT,
  author        TEXT,
  published_at  TIMESTAMPTZ,
  lang          VARCHAR(16),
  content_md    TEXT,                            -- 清洗后正文 Markdown
  content_text  TEXT,                            -- 纯文本（检索 / LLM 输入）
  word_count    INTEGER,
  summary       TEXT,                            -- LLM 摘要
  status        VARCHAR(16) NOT NULL DEFAULT 'pending',
                -- pending → processing → ready / failed
  error         TEXT,
  snapshot_path TEXT,                            -- app_data 内 .html.gz 相对路径
  search_tsv    tsvector,                        -- jieba 分词后写 simple tsvector
  embedding     vector(512),                      -- bge-small-zh-v1.5；换模型需重嵌入
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, url_hash)
);
CREATE INDEX idx_articles_user_created ON articles (user_id, created_at DESC);
CREATE INDEX idx_articles_tsv ON articles USING GIN (search_tsv);
CREATE INDEX idx_articles_vec ON articles USING hnsw (embedding vector_cosine_ops);
CREATE INDEX idx_articles_title_trgm ON articles USING GIN (title gin_trgm_ops);
CREATE INDEX idx_articles_domain ON articles (user_id, domain);

CREATE TABLE tags (
  id      BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name    VARCHAR(64) NOT NULL,
  UNIQUE (user_id, name)
);

CREATE TABLE article_tags (
  article_id BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  tag_id     BIGINT NOT NULL REFERENCES tags(id)    ON DELETE CASCADE,
  PRIMARY KEY (article_id, tag_id)
);
CREATE INDEX idx_article_tags_tag ON article_tags (tag_id);

CREATE TABLE annotations (
  id          BIGSERIAL PRIMARY KEY,
  article_id  BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  user_id     BIGINT NOT NULL REFERENCES users(id)    ON DELETE CASCADE,
  type        VARCHAR(16) NOT NULL,          -- highlight | note | ai
  quote_text  TEXT,                          -- 选中文本；全文笔记为 NULL
  anchor      JSONB,                         -- {"prefix": "…前30字", "suffix": "…后30字", "occ": 第n次出现}
  note        TEXT,                          -- 手写内容（高亮可为空）
  ai_result   TEXT,                          -- LLM 对选中片段的产出
  color       VARCHAR(8)  DEFAULT '#ffd54f',
  status      VARCHAR(16) DEFAULT 'done',    -- done | processing | failed（AI 批注用）
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_annotations_article ON annotations (article_id, created_at);

CREATE TABLE jobs (
  id           BIGSERIAL PRIMARY KEY,
  user_id      BIGINT,
  article_id   BIGINT,
  type         VARCHAR(24) NOT NULL,     -- extract | analyze | embed | annotation_ai | reindex（仅重算 tsv）
  status       VARCHAR(16) NOT NULL DEFAULT 'queued',  -- queued|running|done|failed
  priority     INTEGER NOT NULL DEFAULT 5,
  attempts     INTEGER NOT NULL DEFAULT 0,
  max_attempts INTEGER NOT NULL DEFAULT 3,
  payload      JSONB NOT NULL DEFAULT '{}',
  error        TEXT,
  locked_at    TIMESTAMPTZ,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at  TIMESTAMPTZ
);
-- 部分索引：只索引待领取任务，领取扫描极快
CREATE INDEX idx_jobs_claim ON jobs (priority, id) WHERE status = 'queued';
```

**设计要点**

- `articles.embedding` 维度由模型决定（bge-small-zh-v1.5 = 512）。更换模型流程：`ALTER TABLE articles ALTER COLUMN embedding TYPE vector(N)` → 跑 `reembed` 管理命令全量重算。
- ORM 使用 pgvector-python 官方 SQLAlchemy `Vector` 类型绑定，不手写列类型与距离表达式。
- `search_tsv` 由 worker 在正文 / 摘要变化时重算：`to_tsvector('simple', jieba分词以空格连接(标题 + 摘要 + 正文))`；查询侧用同样分词方式构造 `tsquery`，保证两侧一致。
- HNSW 索引适合万级 ~ 百万级向量的近实时近邻检索；`pg_trgm` 索引兜底标题模糊匹配与短查询。
- 所有业务表带 `user_id`，查询基类统一注入 `user_id = 当前用户` 过滤，杜绝越权。

### 4.3 异步任务流水线

**状态机（article.status × 任务链）**

```
POST /articles {url}
  └─ 建 article(status=pending) + job(extract)

worker: extract
  ├─ 成功 → 写 content_md / content_text / 快照 / 元数据
  │          article.status=processing → 入队 job(analyze)
  └─ 失败 → 重试≤2（抓取层）仍失败 → article.status=failed(error)
             补救：用户手动粘贴文本（POST /articles/{id}/retry 带 text）
                   → 直接入队 analyze

worker: analyze
  ├─ 成功 → 写 summary + tags（关联/复用已有标签）→ 入队 job(embed)
  └─ 失败 → 重试≤3（指数退避）→ article.status=failed；可 reanalyze

worker: embed
  ├─ 成功 → 写 search_tsv + embedding → article.status=ready
  └─ 失败 → 重试≤3 → failed；可 reanalyze
```

**worker 实现要点**

- 领取任务（原子、无锁竞争）：

```sql
UPDATE jobs SET status='running', locked_at=now()
WHERE id = (
  SELECT id FROM jobs
  WHERE status = 'queued'
  ORDER BY priority, id
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
RETURNING *;
```

- 并发：worker 进程内固定并发（默认 2，`WORKER_CONCURRENCY` 可调）；LLM 调用超时 60s；抓取超时 20s。
- 幂等：各 handler 以 article 当前状态与已有产物判断跳过或覆盖写，重试安全；article 已被删除时任务直接标记 done 跳过。
- 人工修正（PATCH 标题 / 摘要 / 正文）：入队 `reindex`（仅重算 search_tsv，不重嵌入）与 `embed`（ADR-3 的向量输入含标题 / 摘要，需同步重嵌入，保证向量与内容一致）。
- 僵尸回收：runner 启动及周期性将 `status='running' AND locked_at < now() - interval '15 minutes'` 的任务重置为 `queued`。
- 清理：runner 周期删除 `finished_at < now() - interval '7 days'` 的 done 任务与 `finished_at < now() - interval '30 days'` 的 failed 任务。
- 优雅停机：收到 SIGTERM 后停止领取新任务，当前任务完成后退出；停止超时则将未完成任务安全重置为 queued。
- 客户端感知：轮询 `GET /articles/{id}`（3s → 5s → 10s 退避），或列表按 `status` 过滤刷新。

### 4.4 网页抓取与正文抽取（services/fetcher.py）

1. **URL 规范化**（规范化后计算 `url_hash`）：
   - scheme 缺失时补全为 https；http 与 https 视为同一 URL；
   - host 统一小写，默认端口（80 / 443）省略；
   - 去掉 fragment（`#` 及其后内容）；
   - 移除已知跟踪参数（`utm_*`、`spm`、`fbclid`、`gclid`、`igshid` 等，清单可配置）；
   - 其余 query 参数按参数名排序（顺序不影响去重）；
   - 路径末尾斜杠视为等价（根路径 `/` 除外）；
2. **抓取**：httpx（可配 UA、跟随重定向、20s 超时、自动解压）；按 HTTP 头 → `<meta charset>` → 自动检测的顺序判定编码；
3. **抽取**：trafilatura `bare_extraction`（`favor_recall=True`，输出 Markdown）得正文与元数据；作者 / 发布时间缺失时回退 `og:article:author`、`<time>`、URL 日期正则；中文抽取质量以 20–50 页评测集回归（URL + 期望标题 / 正文断言，fixture 仅存脱敏片段与元数据，不提交整页受版权保护正文）；
4. **质量闸门**：正文字符数 < 200 或抽取失败 → 若配置了 `PLAYWRIGHT_CDP_URL`，经 CDP 连接 browserless 渲染后重抽；仍失败 → `failed`；
5. **快照**：原始 HTML gzip 后存 `app_data/snapshots/{user_id}/{article_id}.html.gz`，路径写入 `snapshot_path`；删除时先提交数据库变更、再删除文件（不与业务事务绑定），遗留孤儿文件由定期清扫任务比对 `snapshot_path` 清理；
6. **长文裁剪**：送 LLM / 向量化的输入超过 ~12k 字符时，按「标题 + 各级小节标题 + 首段 + 尾段 + 各段首句」策略压缩，检索与摘要共享该策略。

### 4.5 LLM 集成（services/llm.py）

- 客户端：openai SDK，`base_url = LLM_BASE_URL`，`api_key = LLM_API_KEY`，模型 `LLM_MODEL`；所有调用集中于此模块，便于 mock 与换厂商。
- **摘要 + 打标**（analyze 任务）：
  - Prompt 要求**仅输出 JSON**：`{"summary": "100-300字摘要", "tags": ["关键词", …]}`；
  - 兼容 `response_format=json_object`（支持时启用）；输出经 pydantic 校验（summary 超长软截断、tags 数量与长度裁剪），解析失败自动发起一轮「修复重问」；
  - 温度 0.2，`max_tokens=800`（为 300 字摘要 + 8 标签留足余量，避免截断导致 JSON 解析失败）；重试 3 次（指数退避）；
  - tag 归一：去空白、去标点、长度截断、数量 3–8、去重；与用户已有 tag 做「小写 + 去标点」比对，命中则复用已有 tag 行（ADR：防同义标签碎片化）。
- **Ask（RAG）**：system 提示「仅依据材料作答，引用格式 [n]，材料无关时明确回答知识库中未找到」；用户消息为 top-5 卡片的「标题 / 时间 / URL / 正文节选（每卡 ≤1200 字）」；输出走 SSE 流式。SSE 经 POST 下发，Flutter 侧基于 dio stream 解析帧（浏览器 EventSource 仅支持 GET，第三方复用同理）。
- **AI 批注**：`summarize` = 100 字内总结选中片段；`explain` = 解释概念 / 作者意图。均带少量前后文辅助。

### 4.6 Embedding（services/embedder.py）

- 模型：`BAAI/bge-small-zh-v1.5`（默认，权重 ~95MB、常驻 ~150MB），sentence-transformers **进程内懒加载单例**（worker 承担文档向量；api 侧为语义检索查询向量懒加载，见 8.2 读路径）；worker 启动即预热加载并输出下载 / 加载进度日志（首次约 130MB），模型文件缓存于 `hf_cache` 卷，支持 `HF_ENDPOINT` 国内镜像。
- 启动校验：`EMBEDDING_DIM` 与数据库列维度不一致时拒绝启动，防止换模型后静默检索劣化。
- 输入拼接：`标题\n摘要(如有)\n各小节标题\n正文前 N 字`，截断至 ~8000 token；
- 输出向量 L2 归一化，检索用余弦相似度（等价内积）；
- 批量接口：重嵌入管理命令按批 32 条处理；
- 换质量档：`EMBEDDING_MODEL=BAAI/bge-m3`（1024 维，api + worker 双进程峰值 ~6GB 内存），需同步 `EMBEDDING_DIM=1024` 并执行重嵌入流程。

### 4.7 检索引擎（services/search.py）

| 模式 | 实现 |
|---|---|
| keyword | query → `jieba.cut_for_search` → 各分词以 OR 连接构造 `to_tsquery('simple', …)`（OR 匹配保证召回，避免 AND 语义零命中）→ `ts_rank_cd` 排序，`ts_headline` 生成命中片段；单 token 或无命中时叠加 `title ILIKE` / trigram 兜底 |
| semantic | query 向量化 → HNSW 余弦 top-k（`ef_search=40`） |
| hybrid（默认） | 两路各取 top-20 → **RRF 融合**：`score = Σ 1/(60 + rank_i)` → 返回 top-N + 每卡片段与分数 |
| ask | hybrid top-5 → 拼 RAG prompt → LLM SSE 流式回答 + 引用列表 |

- 过滤器（tag / domain / 时间范围 / status）在两路 SQL 中共同下推，再融合；
- 所有查询强制 `user_id` 作用域。

### 4.8 认证与安全（core/security.py）

- **密码**：bcrypt（cost=12）。
- **Token**：
  - access：JWT HS256，30 分钟，无状态；
  - refresh：随机 32 字节，sha256 落库，14 天，**使用即轮换**（旧 token 标记 revoked；已 revoked 的 token 再次使用 → 吊销该用户全部 refresh 并要求重新登录，防盗用）。
- **首个管理员**：首个注册用户自动置为 `is_admin = true`，无需初始化命令。
- **数据隔离**：业务查询基类统一 `user_id` 过滤；管理员接口独立前缀与依赖校验。
- **限速**：登录 / 注册按 IP 每分钟 5 次（单实例内存计数即可）。
- **禁用窗口期**：禁用用户即时吊销其全部 refresh token；已签发的 access token 在剩余有效期（≤ 30 分钟）内仍有效，属可接受的窗口期。
- **XSS**：服务端存储清洗后的 Markdown；客户端渲染器不启用原始 HTML 标签注入。快照端点返回不可信的第三方 HTML，响应强制 `Content-Disposition: attachment` + `Content-Security-Policy: sandbox`，防存储型 XSS 与同源钓鱼。
- **配置安全**：`SECRET_KEY` 缺失时拒绝启动；CORS 默认仅同源 + 客户端自注册来源；`/docs` 与 `/openapi.json` 生产默认关闭（`ENABLE_DOCS` 开关，开发环境打开）。

## 5. API 设计

### 5.1 约定

- 前缀 `/api/v1`；JSON UTF-8；鉴权头 `Authorization: Bearer <access>`；
- 错误体统一：`{"code": "ARTICLE_NOT_FOUND", "message": "人类可读信息", "details": {}}`，HTTP 状态码语义化（400/401/403/404/409/422/429/500）；
- 错误码集中在一个模块定义（`code` 枚举），路由层不散落硬编码；
- 分页：`?page=1&page_size=20`（上限 100），响应含 `total`；
- 时间一律 ISO8601 UTC；
- 流式：Ask 使用 SSE（`event: token / citations / done`）。

## 6. 客户端设计（Flutter）

### 6.1 分层架构

```
presentation   pages / widgets / theme（Material 3，深浅色）
      ↑  Riverpod（AsyncNotifier / StateNotifier）
domain         models（freezed）、repository 接口
data           dio api client、DTO、flutter_secure_storage、
               receive_sharing_intent、shared_preferences
```

核心依赖：`flutter_riverpod`、`go_router`、`dio`、`flutter_secure_storage`、`shared_preferences`、`markdown_widget`（可选中富文本）、`receive_sharing_intent`、`window_manager`（桌面窗口记忆）、`flutter_localizations + gen-l10n`（第一天启用，v1 仅中文文案）、`freezed + json_serializable`。

dio 拦截器：401 时单飞（single-flight）刷新 access 后重放请求，避免并发轮换触发 ADR-5 的盗用误判。

### 6.2 页面与导航

| 路由 | 页面 | 要点 |
|---|---|---|
| /login, /register | 认证 | 服务器地址 + 账号密码；token 入安全存储 |
| /home | 知识流 | 搜索框、标签 chips、状态筛选、卡片列表（骨架屏）、FAB 添加、处理中卡片状态轮询 |
| /article/{id} | 阅读视图 | 摘要卡、标签行、Markdown 正文（可选中）、批注侧栏（宽屏）/ 底部弹层（窄屏）、快照入口 |
| /search | 检索结果 | 模式切换（混合/关键词/语义）、过滤、命中高亮片段 |
| /ask | 问一问 | 提问框（v1 单轮问答）、流式回答、引用卡片可点跳转 |
| /tags | 标签管理 | 计数、重命名、删除、合并 |
| /settings | 设置 | 主题、服务器地址、登出、缓存清理 |

桌面端（宽度 ≥ 1000dp）：`LayoutBuilder` 切换为「列表 + 详情」双栏。

### 6.3 阅读与批注实现

- 正文以 markdown_widget 渲染为**可选中**富文本；选中文本后弹出自定义工具条：高亮 / 笔记 / AI 总结 / AI 解释；
- **锚定算法**（ADR-4）：客户端持有全文源串；保存时提取 `quote_text`、前后各约 30 字与出现序号作为 `anchor.prefix/suffix/occ`；渲染时定位 `prefix + quote + suffix` 匹配段，拆分 span 上色；匹配不唯一时按 `occ` 定位第 n 处；
- 锚失效（正文被人工修正）：批注降级为「仅列表展示」并标注「原文已变化」，数据不丢；
- **实现风险**：源串偏移到渲染 span 的映射需处理 Markdown 语法字符（`#`、`*`、链接等）差异；M3 开工前先用 markdown_widget 做选区 / 定位 spike 验证，结论回写 ADR-4；
- 全文级笔记：`quote_text = null`，仅显示在批注列表。

### 6.4 系统集成

- **Android 分享**：`receive_sharing_intent` 监听 `ACTION_SEND`（text/url），冷启动与热启动均进入「添加」页并预填 URL；
- **桌面**：添加对话框自动检测剪贴板中的合法 URL 并预填；`window_manager` 记忆窗口尺寸与位置；
- **打包**：Android 出 APK；Windows 出 MSIX / zip（M5）。

### 6.5 状态轮询与离线（M5）

- 处理中卡片按 3s → 5s → 10s 退避轮询详情，完成后刷新列表项；应用退到后台时暂停轮询，回前台恢复；
- 离线：drift/sqlite 缓存最近浏览的卡片正文与批注，离线时只读打开，联网后同步拉取。

## 7. 部署设计

### 7.1 docker-compose 拓扑

```yaml
services:
  db:
    image: pgvector/pgvector:pg16          # 官方 pgvector 镜像

      POSTGRES_USER: kb

  api:
    build: ../server                        # 同一镜像
    command: sh -c "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8000"   # 启动自动迁移
    environment: <<来自 .env>>
    volumes: [app_data:/data/app]
    restart: unless-stopped
    depends_on: { db: { condition: service_healthy } }
  worker:
    build: ../server                        # 同一镜像
    command: python -m app.workers.runner
    volumes: [app_data:/data/app, hf_cache:/data/hf]

  render:        # 可选：docker compose --profile render up -d

    image: browserless/chrome
  proxy:         # 可选：docker compose --profile proxy up -d
```

### 7.3 备份与恢复

- **备份**（`deploy/backup.sh`，建议 crontab 每日执行）：
  1. `pg_dump -Fc` 导出数据库；
  2. `tar czf` 打包 `app_data` 卷（快照）；
  3. 产物落 `backups/YYYY-MM-DD/`（建议另拷至异地 / 对象存储）。
- **恢复**（`deploy/restore.sh`）：`pg_restore` + 解包 `app_data` → `docker compose up -d`；文档含演练步骤。

### 7.4 TLS 与反向代理

生产建议前置 Caddy / Nginx：`443 → api:8000`；SSE 路径需关闭响应缓冲（`proxy_buffering off` / Caddy `flush_interval -1`）。注意请求体限制：手动粘贴正文最大约 1.5MB，Nginx 需调大默认 `client_max_body_size`（建议 5m）。

| postgres | 200–500MB |

## 8. 关键流程时序

### 8.1 采集入库（主干流程）

```
客户端        api                        worker                     db/LLM
  │ POST /articles │                          │                        │
  │───────────────►│ 鉴权→URL规范化→去重校验     │                        │
  │                │ 建 article(pending)+job ──►│ (落库)                 │
  │◄── 202 ────────│                           │                        │
  │                │        worker 领取 extract │──► httpx 抓取          │
  │                │        写正文/快照/元数据    │──► trafilatura 抽取    │
  │                │        入队 analyze        │                        │
  │                │        领取 analyze ───────│──► LLM 摘要+tags       │
  │                │        写 summary/tags     │                        │
  │                │        入队 embed          │                        │
  │                │        领取 embed ─────────│──► 本地模型向量化       │
  │                │        写 tsv+embedding    │                        │
  │  轮询 GET /articles/{id}                    │                        │
  │◄── status=ready（含 summary/tags）           │                        │
```

### 8.2 混合检索

api 收到 query → jieba 分词（keyword 路 tsquery）+ embedder 向量化（semantic 路）→ 两路 SQL 并行 → RRF 融合 → 片段与分数 → 响应。ask 模式在此基础上把 top-5 喂给 LLM 做 SSE 流式回答。

### 8.3 AI 批注

选中文本 → `POST /annotations`（即时落库，highlight/note 立即可见）→ `POST /annotations/{id}/ai` → job(annotation_ai) → worker 调 LLM → 回写 `ai_result` → 客户端轮询批注状态刷新。

### 8.4 认证

登录 → 发 access(30min) + refresh(14d) → access 过期时客户端用 refresh 轮换取新对 → refresh 被吊销后复用 → 服务端吊销该用户全部 refresh 并要求重新登录。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 反爬 / JS 渲染页面抓取失败 | 采集覆盖面 | render 可选服务兜底 + 手动粘贴文本通道 + 失败原因可读可重试 |
| LLM 输出 JSON 不稳定 | 分析失败率上升 | json_object 模式 + 修复重问 + 重试 3 次 + 人工重新分析入口 |
| 切换 bge-m3 质量档内存吃紧 | 双进程峰值 ~6GB | 默认 bge-small-zh-v1.5（~150MB）；bge-m3 仅在 ≥6GB 内存档位使用，切换需重嵌入 |
| jieba 分词歧义 | 关键词检索召回不足 | 混合检索中语义路兜底；演进项 zhparser 自定义镜像 |
| 超长文章超出模型窗口 | 摘要 / 向量截断失真 | 12k 字符结构化裁剪策略；演进项 map-reduce 分段摘要 |
| 单实例故障 | 服务中断 | 每日自动备份 + compose 一键重建 + 恢复演练文档 |
| 云端 LLM 数据出网 | 隐私顾虑 | 向量化本地化；LLM 可随时切换为本地推理（Ollama 等 OpenAI 兼容端点） |
| Markdown 锚定偏移映射复杂 | 批注定位错位 | M3 前 spike 验证选区 / 定位方案；匹配失败降级列表展示（FR5.6） |

## 11. 未来演进路线

1. **检索增强**：zhparser 自定义 PG 镜像提升中文分词；分块多向量 + 片段级命中高亮；
2. **全离线模式**：接入 Ollama 容器（OpenAI 兼容）承担摘要与问答，数据完全不出服务器；
3. **采集增强**：浏览器插件（一键收藏当前页）、RSS / 书签批量导入、定时重抓；
4. **资料类型扩展**：PDF / EPUB 解析入卡；
5. **知识网络**：卡片间双向链接、相关卡推荐、轻量知识图谱视图；
6. **协作**：只读分享集 / 团队空间；
7. **客户端**：离线全文缓存与多端同步、桌面全局快捷键、移动小组件。
