## 1. 项目概述

### 1.1 背景与目标

个人与小型团队在学习、研究、工作中会阅读大量网页资料，这些资料散落在浏览器书签与聊天记录中，难以沉淀、总结与再次检索。本项目构建一个**自托管的跨平台知识库系统**，实现：

1. 用户把网页 URL 发送给系统，系统自动抓取并清洗正文；
2. 由 LLM 自动生成摘要与关键词标签，与原文一并持久化；
3. 支持关键词检索与自然语言语义检索；
4. 在安卓手机与电脑（Windows/macOS/Linux）上均可随时查阅与批注；
5. 服务端以 Linux Docker 部署，数据完全自持。

一句话定位：**「收藏即归档，归档即检索」**。

### 1.2 目标用户

- **主要**：有资料沉淀习惯的个人用户；自托管，具备基本 Docker 使用能力。
- **次要**：小型团队（≤ 10 人）共用一台服务器，各自维护独立知识库。

### 1.3 项目范围

**本期范围内（In Scope）**

- 网页 URL 采集、正文抽取、原始 HTML 快照；
- 手动粘贴文本建卡；
- LLM 摘要、关键词打标、选中片段总结/解释；
- 关键词检索（中文分词）、语义检索、混合检索、带引用的问答（Ask）；
- 批注：高亮、手写笔记、AI 总结选中文本、全文级笔记、导出；
- 多用户注册登录与数据隔离；
- Flutter 客户端：Android + Windows（优先）/ macOS / Linux；
- Docker Compose 一键部署、备份与恢复方案。

**本期范围外（Out of Scope，见架构文档第 11 章演进路线）**

- 浏览器插件、RSS 订阅导入、书签批量导入；
- PDF / EPUB / 图片型资料解析；
- 客户端离线全文缓存与多端冲突合并（M5 仅做轻量只读缓存）；
- 团队协作共享、细粒度权限（本期用户间数据完全隔离，不共享）；
- 桌面全局快捷键（客户端失焦 / 后台时的快捷键交互）、移动小组件等增强交互；
- 英文文章适配：LLM 摘要 / 打标 / 检索按中文设计与产出，暂不适配英文内容（网页抓取本身不受限）。

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 知识卡（Article） | 一条知识条目，由一次采集或手动粘贴产生，含正文、摘要、标签、批注 |
| 快照（Snapshot） | 采集时保存的原始 HTML（gzip），用于原文回溯与防死链 |
| 批注（Annotation） | 用户或 AI 对全文或选中文本产生的注释，类型：高亮 / 笔记 / AI |
| 锚点（Anchor） | 批注在文内的定位信息（引用文本 + 前后文各约 30 字 + 出现序号） |
| 语义检索 | 用 embedding 向量按含义相似度检索 |
| 混合检索 | 关键词与语义两路结果 RRF 融合排序 |
| 问一问（Ask） | 检索 top-k 知识卡交给 LLM 生成带引用来源的回答 |
| 知识流水线 | extract（抓取抽取）→ analyze（摘要打标）→ embed（向量化）三段异步任务 |

## 3. 用户角色

| 角色 | 权限 |
|---|---|
| 普通用户 | 管理自己的知识卡、标签、批注；检索范围仅限自己的数据 |
| 管理员 | 普通用户全部权限 + 用户管理、注册模式控制、任务队列管理 |

首个注册的用户自动成为管理员。

## 4. 功能需求

### 4.1 F1 网页采集

**描述**：用户提交网页 URL，系统异步抓取并抽取正文，生成知识卡。

**需求明细**

| 编号 | 需求 |
|---|---|
| FR1.1 | 支持三种提交入口：客户端内手动输入 URL、Android 系统分享菜单（浏览器分享 → 知识匣）、桌面端「添加」对话框打开时自动检测剪贴板中的合法 URL 并预填（客户端失焦 / 后台时无任何快捷交互） |
| FR1.2 | 抓取使用常规浏览器 UA（可配置），默认超时 20s、自动重试 2 次，跟随重定向 |
| FR1.3 | 正文抽取剥离广告、导航、页头页脚等噪音，产出：标题、作者（若有）、发布时间（若有）、正文 Markdown、正文纯文本 |
| FR1.4 | 采集成功时同时保存原始 HTML 快照（gzip），详情页可回看原文 |
| FR1.5 | 同一用户重复提交规范化后相同的 URL 时，提示已存在并跳转旧卡，不重复入库 |
| FR1.6 | 抓取失败（反爬 / 网络 / JS 渲染）时：卡片标记失败且原因可读；可选无头浏览器服务对疑似 JS 渲染页面兜底重试；用户可随时手动粘贴文本补救 |
| FR1.7 | 提交后接口立即返回卡片（状态：排队中）；处理进度在列表与详情页轮询可见 |
| FR1.8 | 支持 HTTP/HTTPS；自动识别常见字符编码（UTF-8 / GBK 等） |

**验收标准**

- 提交典型新闻 / 博客 / 文档页 URL，1 分钟内正文入库且无广告噪音；
- 重复提交同一 URL 不产生第二张卡；
- 无效 URL 或断网时卡片状态为失败，失败原因可读，且可手动粘贴文本完成建卡。

### 4.2 F2 LLM 分析与存储

**需求明细**

| 编号 | 需求 |
|---|---|
| FR2.1 | 正文入库后自动触发 LLM 分析，产出：① 100–300 字中文摘要；② 3–8 个关键词标签（摘要与标签均以中文产出，暂不适配英文文章） |
| FR2.2 | 打标时优先沿用用户已有标签的措辞，避免同义标签碎片化 |
| FR2.3 | 原文（正文 Markdown + 快照）、摘要、标签三者同时持久化并相互关联 |
| FR2.4 | 分析为异步任务：接口秒级返回；LLM 调用失败自动重试（指数退避，最多 3 次），仍失败则卡片标记失败原因，用户可一键重新分析 |
| FR2.5 | LLM 通过 OpenAI 兼容接口接入，BASE_URL / API_KEY / 模型名全部由环境变量配置，切换厂商不改代码 |
| FR2.6 | 标签支持重命名、删除、合并（合并后所有关联卡片迁移到目标标签） |
| FR2.7 | 支持人工修正标题 / 摘要 / 正文；修正后自动重算检索索引与向量（详见架构文档 4.3），正文修正后批注按 FR5.6 处理 |

**验收标准**

- 分析完成后详情页同时可见原文、摘要、标签；
- 停用 LLM 服务使分析失败 → 恢复服务 → 一键重新分析成功；
- 合并两个标签后，原标签下的卡片全部挂到目标标签下。

### 4.3 F3 检索

**需求明细**

| 编号 | 需求 |
|---|---|
| FR3.1 | 关键词检索：中文分词全文检索，返回命中片段并高亮；支持按标签、来源域名、时间范围、状态过滤与按时间 / 相关度排序 |
| FR3.2 | 语义检索：输入自然语言（如「关于分布式锁的那些坑」），按语义相似度返回知识卡 |
| FR3.3 | 混合检索（默认模式）：关键词与语义两路结果 RRF 融合排序 |
| FR3.4 | 问一问（Ask）：检索 top-5 卡片后由 LLM 生成回答，回答必须附带引用（卡片标题 + 链接），支持流式输出；知识库无相关内容时明确说明 |
| FR3.5 | 所有检索严格限定当前用户的数据范围 |

**验收标准**

- 中文关键词检索召回正确，命中片段高亮；
- 语义检索在用词不同但含义相近时可召回目标卡片；
- Ask 回答附带可点击的引用来源；无相关内容时拒绝作答而非编造。

### 4.4 F4 跨平台客户端（Flutter）

**需求明细**

| 编号 | 需求 |
|---|---|
| FR4.1 | 一套代码发布 Android（APK）与桌面端（Windows 优先，macOS / Linux 兼容） |
| FR4.2 | 页面：登录 / 注册、知识流（列表）、知识卡详情（阅读视图）、添加、搜索、问一问、标签管理、设置 |
| FR4.3 | 服务器地址与凭据保存在平台安全存储（Android Keystore / Windows DPAPI） |
| FR4.4 | Android 端注册系统分享目标：在浏览器点「分享 → 知识匣」直接进入建卡流程 |
| FR4.5 | 处理中卡片状态自动（轮询 + 退避）更新；列表支持下拉刷新与分页加载 |
| FR4.6 | 适配深色模式；适配手机竖屏 / 平板 / 桌面宽窗口（宽屏列表 + 详情双栏） |

### 4.5 F5 批注

**需求明细**

| 编号 | 需求 |
|---|---|
| FR5.1 | 阅读视图中选中文本弹出操作条：高亮、写笔记、AI 总结选中、AI 解释选中 |
| FR5.2 | 批注保存引用文本（quote）与锚点（前后文各约 30 字 + 第 n 次出现序号）；重新打开时在原位渲染高亮 |
| FR5.3 | 全文级笔记：不选中文本，直接对整张卡写笔记 |
| FR5.4 | AI 批注结果作为批注内容保存，用户可再手写补充；AI 批注为异步任务，失败可重试 |
| FR5.5 | 批注可编辑、删除、换颜色；详情页按文中顺序列出全部批注；每张卡的批注可一键导出为 Markdown |
| FR5.6 | 正文被人工修正导致锚点失效时，批注降级为列表展示并提示「原文已变化」，不丢失 |

**验收标准**

- 选中 → 高亮 → 退出重进，高亮位置正确；
- AI 总结选中片段，结果落库并显示，失败可重试；
- 导出的 Markdown 含引用原文、笔记与 AI 结果。

### 4.6 F6 标签管理

| 编号 | 需求 |
|---|---|
| FR6.1 | 标签页展示用户全部标签及关联卡片数 |
| FR6.2 | 点击标签按标签筛选知识流 |
| FR6.3 | 支持重命名 / 删除 / 合并（同 FR2.6） |

### 4.7 F7 用户与认证

| 编号 | 需求 |
|---|---|
| FR7.1 | 用户名 + 密码注册 / 登录；密码使用 bcrypt 哈希存储 |
| FR7.2 | JWT 认证：短效 access token（30 分钟）+ 可轮换、可吊销的 refresh token（14 天） |
| FR7.3 | 注册模式可配置：开放 / 邀请码 / 关闭（关闭时由管理员在后台建号） |
| FR7.4 | 所有业务数据按 user_id 严格隔离，任何接口不得越权访问他人数据 |
| FR7.5 | 登录 / 注册接口限速（默认每 IP 每分钟 5 次） |
| FR7.6 | 不提供用户自助修改密码；忘记密码由管理员重置（FR8.1），改密后该用户全部 refresh token 失效 |

### 4.8 F8 系统管理

| 编号 | 需求 |
|---|---|
| FR8.1 | 管理员可列出 / 禁用 / 删除用户、重置用户密码 |
| FR8.2 | 管理员可查看任务队列状态（进行中 / 失败任务数与清单）并重试失败任务 |
| FR8.3 | 提供 /healthz（存活）与 /readyz（依赖检查）端点 |
| FR8.4 | 提供一条命令完成数据库 + 快照目录备份，及对应恢复步骤文档 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR1 | 性能 | 提交 URL 到接口返回 < 1s；分析任务 P90 < 30s（含 LLM 耗时，视所配 LLM 服务性能而定）；关键词 / 混合检索 P95 < 500ms（万卡规模） |
| NFR2 | 容量 | 单用户支持 1 万+ 知识卡；单卡正文 ≤ 50 万字符 |
| NFR3 | 安全 | 全链路 HTTPS（反向代理终结）；JWT 签名密钥必配；ORM 防 SQL 注入；Markdown 渲染不启用原始 HTML 注入防 XSS；登录限速 |
| NFR4 | 隐私 | 向量化使用服务器本地模型，正文不因 embedding 出网；仅摘要 / 问答 / AI 批注（总结、解释选中片段）调用云端 LLM 时内容出网；快照与数据库均在本机数据卷 |
| NFR5 | 可靠性 | 任务持久化在数据库，进程重启后自动恢复待处理任务；任务可重试且幂等（重试不产生重复副作用） |
| NFR6 | 可维护性 | Alembic 管理数据库迁移；结构化日志贯穿 API 与任务；配置全部走环境变量；核心服务（抽取 / 检索 / LLM 解析）有单元测试 |
| NFR7 | 兼容性 | 服务端：Linux + Docker Compose；客户端：Android 8+，Windows 10+（macOS 12+ / 主流 Linux 发行版尽力兼容） |
| NFR8 | 资源 | 全套部署建议 ≥ 2 核 CPU / 4GB 内存 / 20GB 磁盘（含本地 embedding 模型） |

## 6. 约束与假设

- **C1** 服务端仅面向 Linux Docker 部署，不考虑裸机或 Windows 服务器。
- **C2** 生成类 LLM 由部署者提供（云端 API 或本地推理服务均可，走 OpenAI 兼容协议）；系统仅内置 embedding 小模型权重（运行时自动下载）。
- **C3** 按单实例部署设计（不做水平扩展），满足个人 / 小团队规模。
- **C4** 客户端不内置完整浏览器：阅读视图渲染清洗后的 Markdown 正文，原文回溯通过快照实现。

## 8. 顶层验收场景清单

1. 手机浏览器分享 URL → 知识匣 → 卡片出现并自动完成摘要 + 标签；
2. 电脑端登录同一账号，看到同一份数据；
3. 关键词搜索、语义搜索、问一问三类检索全部可用，且结果严格隔离于本账号；
4. 选中文本高亮 + AI 总结，重启客户端后高亮仍在原位；
5. 停用 LLM 后卡片可标记失败，恢复后一键重新分析成功；
6. `docker compose up` 一条命令拉起全套服务；备份恢复演练通过；
7. 第二个注册用户看不到第一个用户的任何数据；
8. 注册模式置为「关闭」后，新用户无法自行注册。
